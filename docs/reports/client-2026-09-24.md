## 1. 这一轮补了什么

### 1.1 P2 三个交付物（设计稿 §3.2 / 实施方案 §P2）

| 文件 | 内容 |
|:--|:--|
| `app/client/window.py` | 主窗口：**一个** `Toplevel` 两种状态。展开态 = 宫格 +（教师）汇总面板 +（学生）隐藏开关；最小化态 = 56×56 圆 + 拖动 |
| `app/client/bubblewin.py` | 气泡**卫星窗口** + 右键菜单 + 全局退出热键 + 透明降级 |
| `app/client/__init__.py` | 包导出 |

配套两个计划外文件，理由写在文件头：

| 文件 | 为什么必须有 |
|:--|:--|
| `app/client/theme.py` | `window.py` 与 `bubblewin.py` 共用一套底色/字号；放在任一侧都会循环导入 |
| `app/client/__main__.py` | 没有入口就**跑不起来**，前端也就无法交付验证 |

### 1.2 为什么气泡必须是独立卫星窗口

圆形图标要做透明背景只能靠 `-transparentcolor`，而它**仅 Windows 可用**。若把气泡画进
主窗口，窗口矩形必然包含气泡那块区域，在非 Windows 上就会露出一个包住「气泡 + 圆」的
方块。拆出去之后主窗口最小化态只占约 56×56，视觉上才真的是「一个圆形图标」。

卫星窗口**不持有任何业务状态** —— 内容全由主窗口算好灌进去，所以 D3 的「两种状态
状态一致」不受影响。

### 1.3 `hub` 为什么多了个写端点

P2-4 要求学生端能把隐藏开关**上报**，而可见性裁剪在**服务端**（设计稿 §01.1 / §07.2）——
客户端改不了。原有 `hub` 只有只读的 `GET /snapshot`，于是开关会变成一个「点了没用」的控件。
所以补了 `POST /hidden`：

- 读写分开，而不是往 `GET /snapshot` 上挂参数 —— **GET 不该有副作用**（任何预取或重试
  都可能意外改写别人的可见性）；
- 畸形请求一律 400 并保证服务线程不死（空体、非法 JSON、非对象、非 UTF-8、
  `Content-Length` 不是数字），这些分支由**原始 socket** 测试覆盖 —— `urllib` 造不出这类请求。

### 1.4 往 `app/present/` 补的三个纯函数

| 新增 | 用途 | 为什么不写在 GUI 里 |
|:--|:--|:--|
| `colors.color_for_key(label: str)` | 客户端拿到的是 `"focused"` 这类**字符串键**，不是枚举 | GUI 整体 `omit` 于覆盖率，规则写进去等于没有护栏 |
| `grid.columns_for(count)` | 宫格列数 = `ceil(sqrt(n))` 再夹上限 | 同上；且它是纯几何，可完整单测 |
| `summary.LABEL_TEXT` | 4 个状态的**中文展示名**（专注/困惑/分神/未知） | 与配色同级，属展示规则；放这也是为了强制「键集与分量键集一致」 |

`LABEL_TEXT` 的测试断言用的是**等号**而不是「包含」：多一个键是死数据，少一个键会让
客户端静默退化成显示英文枚举值 —— 两种都是无声劣化。

## 3. 复现方式

```bash

python -m app.client --demo --role teacher
python -m app.client --demo --role student --viewer s03

# 连一个已在跑的 hub
```

**演示为什么走真 HTTP 而不走进程内直调**：「服务端按观看者裁剪」这件事只发生在端点背后。
走直调就永远验证不到 D5 的裁剪与写通道 —— 而那恰恰是本轮最容易做错的地方。

| `global_hotkey` | `true` | `true` | 拿到了系统级 `Ctrl+Alt+Q`；非 Windows 会退为窗口内加速键 |

### 4.1 那 8 格「无结果」不是 bug

学生按 `common.mock.SCENARIOS` **原样轮转**（不做「只挑好看的场景」这种筛选）。
实测各场景在前 4 帧的平滑输出：

| 场景 | 第 1–4 帧的 `final` |
|:--|:--|
| `consensus` | `-` `-` `focused` `focused` |
| `conflict` | `-` `-` `-` `-` |
| `low_light` | `-` `-` `distracted` `distracted` |
| `low_confidence` | `-` `-` `-` `-` |
| `occluded` | `-` `-` `confused` `confused` |
| `single_channel` | `-` `-` `distracted` `distracted` |
| `jitter` | `-` `-` `focused` `focused` |

两点都很关键：

1. **前两帧必然是 `-`** —— 平滑层是「3 中 2」的，窗口没填满就没有可输出的稳定状态。
   这正是演示驱动必须**预热 3 帧**的原因（§7.2）。
2. **`conflict` 与 `low_confidence` 永远没有 `final`** —— 融合层对这两类输入**拒判**
   （输出 `UNKNOWN`），而 `UNKNOWN` 依契约为「本帧无判定」、不参与投票，平滑层因此
   无票可确认。28 名学生里恰好 4+4 人落在这两个场景 → 20 格有状态、8 格显示「无结果」。
   **宫格上留几格「无结果」比伪造成一片整齐的绿更诚实**，它演示的正是设计要的拒判行为。

## 6. D5 端到端实测（真实 HTTP，非 mock）

用客户端自己的 HTTP 通道跑一遍，验证 D5 的四个方向：

```
A3 学生互见      : s02 看 s01 -> state=focused, hidden=False
A6-1 开启隐藏    : POST /hidden -> s02 看 s01 -> state=None, hidden=True
A6-2 自己仍可见  : s01 看 s01 -> state=focused, hidden=True
A7 教师不受影响  : t01 看 s01 -> state=focused, hidden=True
A2 学生无 summary: False（符合预期）
A1 教师不占格    : 't01' 在教师宫格里 -> False（符合预期）
A8 教师气泡分量  : focused:1  confused:1  distracted:2  unknown:0
   在线人数      : 4        分量之和      : 4
```

A6-3（**隐藏后仍能观察未隐藏的同学**）另跑一组对照：把 `s01` 自己的开关打开前后，
它看到的宫格内容是

```
隐藏前: {'s01': 'focused', 's03': 'distracted', 's05': 'confused', 's06': 'distracted'}
隐藏后: {'s01': 'focused', 's03': 'distracted', 's05': 'confused', 's06': 'distracted'}
```

两者**逐项相同** —— 开关只影响「同学能不能看见我」，不影响「我能看见谁」。这一点必须
是单向的：实现成全班级「退回只看自己」是另一回事、语义完全不同。

另外注意 A6-2 那一行：`s01` 隐藏后**自己仍看得见自己**（`state=focused`）。否则开关一按，
自己都不知道自己什么状态 —— 那是坏体验。

## 7. 本轮踩到的坑（都已修）

### 7.1 演示驱动漏调 `publish`，hub 里只有教师

`SerialSession.step_perception` **只产出报告、不登记在线表** —— 登记是 `publish` 的事。
症状很隐蔽：客户端拿到 404 → 界面显示「离线」，看起来像网络问题。修法是 `tick()` 里补
`self.session.publish(report)`，并在注释里写明「漏掉这一步的症状」。

### 7.2 预热不足：首屏一屏空宫格

平滑层是「3 中 2」的，第 1、2 帧窗口没填满，`report.final` 必然是 `None`。
演示驱动原本只跑 1 帧就交给界面，于是打开窗口看到的是 28 格全「无结果」。
修法是 `WARMUP_ROUNDS = 3`（实测第 3 帧出稳定状态）。

### 7.3 `-transparentcolor` 会**静默**不生效

只 `try/except` 是不够的：在部分平台上它既不抛错也不生效，于是界面上出现一块洋红色方块。
修法是 `try_enable_transparency` **设完再回读一次**：

```python
window.attributes("-transparentcolor", TRANSPARENT_KEY)
return str(window.attributes("-transparentcolor")).lower() == TRANSPARENT_KEY.lower()
```

不生效就降级为实心小圆 —— 按设计稿 §05.2，实心圆本身就够「不挡画面」，不必依赖真透明。

### 7.4 两个静态检查的坑（供后续改这个文件的人参考）

- `attributes` 定义在 **`tk.Wm`**（`Tk` / `Toplevel`）而不是 `tk.Misc` —— 参数注解写
  `Misc` 会被 mypy 报 `attr-defined`；
- `bind` 的重载让 mypy 推不出 `lambda` 的参数类型（`Cannot infer type of lambda`），
  改成带注解的嵌套函数即可。

## 9. 复现注意事项

- **CI 不跑 GUI**：`app/client/*` 已在 `pyproject.toml` 的 `coverage omit` 里。CI 五道门禁
  （`guard` / `lint` / `typecheck` / `pytest (3.10)` / `pytest (3.12)`）对它的保障是
  **「ruff 与 mypy 能过」**，不是「界面正确」—— 界面正确靠 `--selftest` 冒烟。
- 因此**判定规则一律不得写进 `app/client/`**：写进去既测不到，也让 CI 无感。
- 本地等价复跑（在仓库根目录）：

  ```bash
  python -m ruff check . && python -m ruff format --check .
  python -m mypy
  python -m pytest --strict-markers --strict-config --cov --cov-report=term-missing --cov-fail-under=80
  python -m app.client --demo --selftest --json --port 0 --role teacher
  ```
