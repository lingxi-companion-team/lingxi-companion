# 可选前端依赖（**只有跑 `python -m app.web` 才需要**）。
#
# ── 为什么单独一个文件，而不是并进 requirements.txt ────────────────────────
# `flet` 不是「跑系统」需要的库，而是**一个可选前端**需要的：
#   * 产品前端 = `python -m app.web`（Flet 统一单页，需求文档 §二.1）；
#   * 本地调试外壳 = `python -m app.client`（Tkinter，**零第三方依赖**）。
# 不跑 Web 前端的人（例如只跑集成链路、只跑压测）不需要装它。
#
# ── 为什么 CI 不装它 ──────────────────────────────────────────────────────
# `.github/workflows/tests.yml` 的 4 个 job 只安装 `requirements-dev.txt`。
# 本文件**刻意不进 CI**，原因有两条，缺一不可：
#   1. `flet[web]` 会连带拉进 fastapi / uvicorn / starlette / pydantic /
#      websockets / httptools / watchfiles / python-dotenv / click / pyyaml /
#      opentelemetry-api 等十余个包 —— 4 个 job 各下一遍纯属浪费，
#      而 `lint` 的 `timeout-minutes` 只有 5 分钟；
#   2. `pyproject.toml` 已把 `app/web/*` 列入 coverage `omit`，
#      **CI 根本不会 import flet** —— 装进 CI 是零门禁收益。
#
# ── 为什么也不进 pyproject.toml 的 [project] dependencies ─────────────────
# 那条约定（见 `requirements.txt` 顶部）管的是「`requirements.txt` ↔ pyproject
# 必须同步」。本文件是**第三个类别**：可选能力，不进 `pip install -e .` 的默认路径。
# 否则任何人只要 `pip install -e .` 就会被强制拉进整套 web 栈。
#
# ── 装法 ──────────────────────────────────────────────────────────────────
#   pip install -r requirements-web.txt
#   python -m app.web                    # 起 hub + 页面，默认 http://127.0.0.1:8600/
#
# ⚠️ **实测版本 = 0.28.3**（flet + flet-web 同版本）。Flet 的控件 API 在
#    0.x 期间并不稳定（0.28 里 `ft.Badge` 是值对象、`ft.Tooltip` 不能当子控件），
#    所以这里写的是**下限**、沿用本仓「浮动 `>=`」的既有约定；
#    换版本后请至少跑一遍 `python -m app.web` 并肉眼确认页面能起来。
flet[web]>=0.28.3
